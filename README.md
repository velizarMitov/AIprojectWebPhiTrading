## 📖 Overview

**PhiTrading** is a full-stack SaaS-style financial intelligence platform that aggregates AI-generated predictions for Forex, Crypto, and Stock markets. Built with a brutal dark aesthetic and an emphasis on speed and security, it delivers curated trading signals to users based on their subscription tier — with full admin control over content management.

The platform leverages **Supabase** as a serverless backend (Auth, PostgreSQL, Storage), enforces **Row-Level Security** at the database layer, and applies **machine learning signal analysis** to surface high-probability trade setups across asset classes.

> Designed to demonstrate production-level architecture patterns: RBAC, secure CRUD with file storage, tiered content delivery, and ML-informed financial signals.

## ✨ Core Features

### 🔐 Role-Based Access Control (RBAC)
The platform implements a four-tier access hierarchy:

| Tier      | Access Level                                  |
|-----------|-----------------------------------------------|
| 🥉 Bronze  | Entry-level signals — major Forex pairs only  |
| 🥈 Silver  | Bronze + Crypto & Altcoin predictions         |
| 🥇 Gold    | Full access — all signals, including ML picks |
| ⚙️ Admin   | Full CRUD control over all platform content   |

Each prediction is tagged with a `required_tier` field. The platform enforces tier gating at both the **UI layer** and the **Supabase RLS policy layer**, preventing unauthorized data access even via direct API calls.

### 🤖 AI-Powered Predictions
The platform surfaces predictions generated by machine learning models trained on historical market data. Signals are categorized across four verticals:

- **Forex** — Major and minor currency pair momentum signals
- **Crypto** — On-chain trend analysis and sentiment-derived entry points
- **Stocks** — Equity breakout detection with volume confirmation
- **ML Picks** — Cross-asset signals with the highest model confidence scores (Gold tier exclusive)

Each prediction card displays the asset, predicted direction, conviction level, and an optional chart image uploaded to **Supabase Storage**.

## 🗄️ Database Schema

### `profiles`
Extends Supabase's built-in `auth.users` table with application-specific metadata.

| Column       | Type        | Description                                          |
|--------------|-------------|------------------------------------------------------|
| `id`         | UUID (PK)   | Foreign key → `auth.users.id`                       |
| `role`       | VARCHAR     | `user` or `admin` (default: `user`)                  |
| `tier`       | VARCHAR     | `Bronze`, `Silver`, or `Gold` (default: `Bronze`)    |
| `created_at` | TIMESTAMPTZ | Profile creation timestamp                           |
| `updated_at` | TIMESTAMPTZ | Last update timestamp                                |

---

### `predictions`
Stores all AI-generated trading signals with tier-gated access control.

| Column            | Type        | Description                                            |
|-------------------|-------------|--------------------------------------------------------|
| `id`              | UUID (PK)   | Auto-generated prediction ID                           |
| `category`        | VARCHAR     | `Forex`, `Crypto`, `Stocks`, or `ML`                  |
| `asset`           | VARCHAR     | Asset symbol (e.g. `EUR/USD`, `BTC/USDT`, `AAPL`)     |
| `prediction_text` | TEXT        | Full signal description and trade rationale            |
| `required_tier`   | VARCHAR     | Minimum tier to view: `Bronze`, `Silver`, or `Gold`    |
| `image_url`       | TEXT        | Public URL of chart image stored in Supabase Storage   |
| `created_at`      | TIMESTAMPTZ | Signal publication timestamp                           |

### 🔒 Row-Level Security (RLS) Policies

RLS is enabled on all tables. Access is enforced at the **PostgreSQL level** — completely independent of application logic.

**`profiles` table:**
```sql
-- Users can only read their own profile
CREATE POLICY "Users can view own profile"
  ON profiles FOR SELECT USING (auth.uid() = id);

-- Users can only update their own profile
CREATE POLICY "Users can update own profile"
  ON profiles FOR UPDATE USING (auth.uid() = id);
```

**`predictions` table:**
```sql
-- All authenticated users can read predictions (tier filtering handled in app)
CREATE POLICY "Authenticated users can read predictions"
  ON predictions FOR SELECT TO authenticated USING (true);

-- Only admins can insert predictions
CREATE POLICY "Admins can insert predictions"
  ON predictions FOR INSERT TO authenticated
  WITH CHECK (
    (SELECT role FROM profiles WHERE id = auth.uid()) = 'admin'
  );

-- Only admins can update predictions
CREATE POLICY "Admins can update predictions"
  ON predictions FOR UPDATE TO authenticated
  USING (
    (SELECT role FROM profiles WHERE id = auth.uid()) = 'admin'
  );

-- Only admins can delete predictions
CREATE POLICY "Admins can delete predictions"
  ON predictions FOR DELETE TO authenticated
  USING (
    (SELECT role FROM profiles WHERE id = auth.uid()) = 'admin'
  );
```

> **Tier Filtering Note:** Content gating by tier (Bronze/Silver/Gold) is enforced at the application layer in `auth.js`, applying a tier hierarchy (`Gold ⊇ Silver ⊇ Bronze`) to filter the predictions array before rendering. This complements the RLS policies to create a two-layer access control system.

## 🧠 ML Models & Signal Generation

PhiTrading's prediction engine integrates machine learning algorithms applied to live and historical market data. Signals are scored, filtered by confidence threshold, and published to the appropriate tier.

### Signal Models

| Model                           | Application                                                                                   | Output                              |
|---------------------------------|-----------------------------------------------------------------------------------------------|-------------------------------------|
| **Trend Analysis (EMA)**        | EMA crossover detection on 4H/1D candles to identify medium-term directional momentum         | Trend direction + strength score    |
| **Sentiment Analysis (NLP)**    | NLP pipeline over financial news and social feeds to derive market sentiment polarity         | Bullish / Bearish / Neutral score   |
| **Volatility Breakout**         | Bollinger Band squeeze + ATR expansion to identify imminent breakout zones                    | Entry zone + expected range         |
| **Volume Anomaly Detection**    | Statistical comparison of current volume vs. 20-period average to confirm or reject moves     | Confirmation / Divergence flag      |
| **ML Ensemble Picks**           | Weighted ensemble classifier combining all model outputs to surface highest-probability setups | Composite confidence score (0–100%) |

### Signal-to-Tier Mapping

```
Bronze  →  Trend Analysis signals (Forex only)
Silver  →  Bronze + Sentiment Analysis + Volatility Breakout (Forex + Crypto)
Gold    →  All signals + ML Ensemble Picks (all asset classes)
```

> Gold-tier users receive only cross-validated signals confirmed by a minimum of **3 independent model outputs** before publication.

## 🚀 Installation & Setup

### Prerequisites
- [Node.js](https://nodejs.org/) v18+
- [npm](https://www.npmjs.com/) v9+
- A [Supabase](https://supabase.com) account and project

### 1. Clone the Repository

```bash
git clone https://github.com/your-username/phi-trading.git
cd phi-trading
```

### 2. Install Dependencies

```bash
npm install
```

### 3. Configure Supabase

The Supabase client is pre-configured in `supabase.js`. For production deployments, move credentials to environment variables:

```env
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_ANON_KEY=your-anon-key
```

### 4. Initialize the Database

1. Open the [Supabase SQL Editor](https://supabase.com/dashboard)
2. Run the full contents of `schema.sql` to create tables and RLS policies
3. In **Storage**, create a bucket named `prediction_images` and set it to **public**

### 5. Create the Admin User

Register via the app UI, then promote to admin in the SQL Editor:

```sql
UPDATE profiles
SET role = 'admin'
WHERE id = (
    SELECT id FROM auth.users WHERE email = 'your-admin@email.com'
);
```

### 6. Start the Development Server

```bash
npm run dev
```

Navigate to **http://localhost:5173**

## 🛡️ Security Architecture

| Layer               | Mechanism                                                                        |
|---------------------|----------------------------------------------------------------------------------|
| **Authentication**  | Supabase Auth — JWT sessions, bcrypt password hashing, no plaintext credentials  |
| **Authorization**   | PostgreSQL RLS — enforced server-side, independent of application code           |
| **XSS Prevention**  | Content Security Policy (CSP) meta tag in `index.html`                           |
| **Storage Access**  | Public bucket with path-based organization; write operations require active auth |
| **Admin Gating**    | `profiles.role === 'admin'` check before rendering any CRUD interface elements   |
| **Input Safety**    | All queries parameterized through Supabase client — no raw SQL concatenation     |

## 🐛 Troubleshooting

| Issue                          | Solution                                                                               |
|--------------------------------|----------------------------------------------------------------------------------------|
| Site blank / broken layout     | Check for `<\/script>` in HTML — remove backslash from closing script tags             |
| SweetAlert2 blocked by browser | Add `cdn.jsdelivr.net` to `script-src`, `style-src`, `font-src` in CSP meta tag       |
| Edit buttons not responding    | Use `.closest('.edit-btn')` in event delegation — SVG children absorb direct clicks   |
| `confirm()` dialog suppressed  | Never call `confirm()` inside `async` handlers — use synchronous outer event handler  |
| Profile not found on login     | Verify `profiles` row was auto-created on signup; check RLS SELECT policy              |
| Image upload failing           | Confirm `prediction_images` Storage bucket exists and is set to public                 |
| ES module import errors        | Must serve via HTTP (not `file://`) — use `npm run dev` or `python -m http.server`     |
